# 0032. Tags as plain names on tracks and playlists; found tags stand in until edited

## Context
The user wants tags: some already exist in their files and DJ libraries, others they make in MCO.
A track can have several, playlists can have them too, the playlist builder should look at them
(on by default), and playlists should show how their tags overlap (a Venn diagram), with length
and tempo alongside (2026-09-25).

## Decision
- **A tag is a name**, compared without case (the first spelling is kept), tidied by `cleanTag`:
  single spaces, no leading `#`, at most 40 characters. No ids, no colour table: a tag's colour is
  a stable hash of its name into the playlist palette.
- **On tracks**: `Track.tags` is the user's list. It is absent until they first edit that track's
  tags; until then `tagsOf(track)` returns the **found** tags, read from:
  - the Grouping field (ID3 `TIT1`/`GRP1`, Vorbis `GROUPING`, MP4 `©grp`; rekordbox XML
    `Grouping`, Apple `Grouping`), split on `, ; / |`;
  - rekordbox **My Tag** written into the comment as `/* Tag / Tag */`;
  - `#hashtags` in the comment.
  So re-importing never brings back a tag the user removed, and nothing has to be migrated.
- **On playlists**: `List.tags`. The collection keeps `tags` too: tags made in MCO, so a new tag is
  offered while nothing uses it yet. Rename and delete work across tracks, playlists and that list.
- **Filters**: Tags and Genre join Quality and Format as value filters (ticks = show only; any
  within a group, all groups together). Each filterable column's header opens its own list (▾),
  counted over the view with the other groups' filters applied.
- **Playlist builder**: "Look at tags" is on by default. Wanted tags default to the starting and
  included tracks' own; the user can change them. "Prefer" adds up to 3 points to a candidate's
  score (`tagFit`: full marks for two of the wanted tags, or all of them if fewer), next to tempo
  (2), keys (2.5) and rating (4). "Only these" keeps just tracks with one of them; tags to avoid
  drop tracks. A saved playlist gets the tags it looked for.
- **Insights** (`core/library/insights.ts`): length, BPM flow by position, keys and how many
  transitions are harmonic (`keyFit` ≥ 0.5), quality mix, tag counts and a Venn of up to three
  tags (the three most used, or the ones clicked). Shown under a playlist (hideable) and in the
  builder.

## Alternatives considered
- Copy found tags into `Track.tags` at import: simpler reads, but a re-import re-adds tags the user
  deleted, and every existing track would need a migration.
- Tag records with ids and colours: renames would be cheaper, but files stay readable by hand only
  with names, and colour choice wasn't asked for.
- Area-proportional Venn circles: harder to read with small counts; equal circles with the counts
  printed say more.

## Consequences
- Renaming a tag rewrites every track that has it (one pass, sharded writes).
- Found tags depend on the Grouping and comment fields being read; Engine DJ, Traktor and Serato
  imports don't carry Grouping today, so their tracks' tags come from the files once analysed.
- Writing tags back to files or DJ apps is out of scope (ADR 0010).
