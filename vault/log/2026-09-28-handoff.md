# Handoff, 2026-09-28: phones, streaming, and the user's second list

If the session ends midway, carry on from here. Work happens on `home-engine` and is fast-forwarded to
`main`. Batches ship one at a time: `npm run check`, Vitest, the full Playwright suite, the vault in
the same commit, then deploy (a `home-v*` tag when `home/` changes). The user hand-tests each batch.

## The user's list (2026-09-28)
1. **Sign in on another device (a phone) and browse and play** the cloud-synced library, without
   making a collection or GLUE folder there. Send songs from the phone to a computer running GLUE
   Home, without the phone having a collection.
2. **A mobile UI that works:** a library explorer and player. Today every page falls apart on a phone.
3. **Stream instead of downloading the whole song first;** GLUE Home does the heavy lifting.
4. **Probable duplicates:** they can't be moved or deleted, and can't be confirmed as duplicates.
5. **Playlist stats:** songs all at 70 BPM, yet Tempo says 70–140, average 115.
6. **Rename playlists** with a slow second click, as songs are edited.
7. **Genres like tags:** a list that grows, to pick from.
8. **"Not a problem" on a song's page**, to clear a false caution by hand.
9. **Another quality false positive:** a promo WAV flagged "Brick-wall cutoff at 20.3 kHz"; with the
   spectrogram floor under −120 dB there's real content above it.
10. **macOS:** GLUE Home sometimes isn't in the Cmd-Tab switcher.
11. **The tags pop-up's background** doesn't cover the panel (track page, table rows, the Tags
    button).
12. **Browse the library** by artists, albums and more, under All tracks.

## Decisions taken with the user
- **A phone (or any browser without a GLUE folder), signed in:** the merged library of all the
  account's devices opens by itself and is remembered there. Edits go to the owning computers.
- **Streaming:** the original file, by byte range, from GLUE Home. Transcoding for mobile data can come
  later.
