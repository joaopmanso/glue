## Open bug: a song sent to the desktop has no analysis or waveform there
**Seen (user, 2026-09-26):** the song was sent from the laptop (no GLUE Home there) to the desktop
(GLUE Home 0.4.0, direct link working). On the desktop:
1. the track page says the song is on the Laptop and not analysed; the yellow button downloads and
   analyses it;
2. back in the library the row has no waveform;
3. after a refresh the track page again says "on Laptop, not analysed".

**Cause (read from the code, not yet fixed):**
- On the desktop the song is the **laptop's track** (cloud overlay), marked by
  `incoming.show()` (`src/lib/incoming.svelte.ts`) with `remote.via = { home, incoming }` pointing at
  the copy in the desktop's incoming folder. It isn't a separate TO BE SORTED row (ADR 0048's dedupe).
- Only **playing** follows `via` (`remoteFiles.source()` / `get()` in `src/lib/remoteFiles.svelte.ts`).
  The other paths use only `remote.incoming` (set on unmatched `in…` rows) and otherwise ask the
  laptop's GLUE Home, which doesn't exist:
  - `remoteFiles.details(t)`: `r.incoming` is empty, `homeFor(t)` is null, so it returns null. The
    track page (`src/ui/library/TrackDetail.svelte`, the `t.remote && !ask && lib.canRead(t)` branch)
    then shows the summary state with the yellow analyse button.
  - `remoteFiles.thumbs(ts)`: the incoming shortcut (`waiting`) only takes `t.remote?.incoming`, so
    the waveform isn't read from `i/<name>.thumb.bin`.
  - The summary GLUE Home made on arrival (`IncomingFile.summary`) is applied only to unmatched rows
    (`analysis.set(id, …)` in `show()`), never to the matched track, so the row and page look
    unanalysed when the laptop hadn't analysed it.
  - An analysis made with the yellow button is for a remote (overlay) track: it isn't saved and no
    waveform is stored, so it's lost on refresh.
  - The track page's "on Laptop" text uses `remote.name` only; it doesn't say the file is also here,
    waiting in TO BE SORTED.

**Fix to make:**
- One helper in `remoteFiles`: the incoming copy of a track = `r.incoming && r.home ? {home: r.home, name: r.incoming} : r.via`,
  used by `details()`, `thumbs()` and `cacheFiles()` callers (the direct link is used when
  `localHome.for(home)`).
- In `incoming.show()`, when a matched track has no analysis in `s.analysis`, set GLUE Home's summary
  on it, and remember it in `touched` so it's removed when the song leaves TO BE SORTED.
- Track page: for a track with `via`, say "Also on this computer, in TO BE SORTED" and play and
  analyse from that copy, with no "on Laptop" warning.
- e2e: the desktop's side of "send songs to a GLUE Home…": the laptop's track (overlay) with the same
  file waiting on the desktop shows its waveform and full track page with no analyse button, also
  after a reload. The current "local link" e2e covers only an unmatched song.
